I rechecked these against cases.csv.gz and similarity_j1_costs.md:
- The compute split is right: 99.17M of 101.75M planning controls (97.5%) went into collecting demonstrations.
- The worker ran for about 50 minutes.
- Walking: 0/256 for children trained on MPPI data, 35/256 for children trained on SAC data.
- The missing-tail penalty makes up 86% of the score on average, and survival ranged from 30 to 1,000 controls.
1. Compute wasn’t the cost. The run was 50 minutes on one machine. By git timestamps, about 3 hours passed between the previous result’s commit (20:30) and J1’s last commit (23:38). Two of J1’s four commits fix publication and memory accounting. The overhead is the frozen-protocol, audit and publication machinery, not the 99M controls.
2. The motion score couldn’t vary, by design. The agent says this “warrants checking.” The saved data already settles it:
   - The score sits near 2 for any child that doesn’t follow the teacher in lockstep.
   - A child that stays up but drifts from the teacher’s timing builds up error at 3.3–4.1 per step. That is about the same as the penalty of 4 charged for missing time. So falling at control 30 and staying up for all 1,000 controls score the same.
   - The one MPPI-trained child that survived all 1,000 controls got the worst score, 2.04.
   - Even the SAC-trained children that fell scored 1.62–1.90.
   - With no MPPI-trained child tracking its teacher, the frozen requirement of a 0.1 standard deviation could not be met.
3. The training budget was far too small for anything to learn. J1 gave each child one trajectory (1,000 rows) and 2,000 updates. The positive-control run (runs/2026-11-02_student_positive_control_001) used the same 128-unit network with 9,000 rows and 10,000 updates, and its SAC clones walk 94/96. J1’s children trained on SAC’s own trajectories walked only 14%. “Demonstration source matters under this fitter” mostly says the fitter was starved.
4. “Planner memory matters” is neither new nor evidence against jitter.
   - J1’s test compared MPPI’s carried plan with a zeroed plan, which is a cold start, so the action was bound to change.
   - The earlier consistency probe had already measured this: the carried plan shifts the action by MSE 0.25, against 0.02 from sampling randomness.
   - Kendall had also said it directly: MPC only works because each step plans around the previous plan.
   - The update-noise runs showed the carried plan itself carries leftover sampling noise. Depending on the plan and being jitter are not opposites.
5. The pre-update scores mostly described the teacher. The children started from untrained networks, which fall immediately. Score D, for example, only spans 1.89–1.99.
   - The children did vary: average survival per episode ranged from 33 to 379 controls, an 11x spread.
   - The two student seeds trained on the same MPPI trajectory differ by 46–130 controls.
   - I checked survival against each score. None tracks it: Spearman correlations run from −0.18 to +0.41, over 16 children from 8 teachers. Using survival as the outcome would not have rescued the five candidates.
1. Don’t run J1.1-B, and don’t run the agent’s cheaper pilot as described either. Both keep the 1,000-row, 2,000-update budget and the same motion score. The jitter test predicts that fine-tuning the SAC-trained children on MPPI data would mostly erase their walking: 10% MPPI-like jitter cut walking from 94/96 to 32/96.
2. Fix the outcome measures first, at zero compute. Use time-to-fall and walking as outcomes. If you keep a motion score, compute it only over the time both trajectories are running, and report survival separately so the score can’t saturate.
3. Build the similarity benchmark where outcomes actually vary, from data you already have.
   - runs/2026-11-02_jitter_tolerance_001 already ranges from 94/96 down to 0/96.
   - It also has a sharp test case: white jitter at 10% walks 51/96, while slow jitter at 10% walks 0/96.
   - Train at the positive-control budget with several student seeds.
   - Score J1’s five candidates plus on-policy disagreement. On-policy disagreement separated walkers almost perfectly after the fact (AUC 0.996), so it’s the lead to confirm. Pick the best on some seeds and confirm it on fresh ones.
   - This takes minutes and needs no new MPPI runs.
4. Only then handle MPPI. A single fresh MPPI query at a student’s state is mostly noise. So a similarity to MPPI has to compare motion over its planning horizon or a closed-loop rollout, not one-step torques.

The pushed docs/sac_continuation_results.md still cites S1.1 as “even oracle clones fail”, which needs correcting.
