# Saved guided-data comparison v3.1

Frozen before any new inference, learning or physics. This closes the comparison that v2's action-agreement proxy prevented. It is a data intervention using the two already recorded successful higher-weight guided episodes, paired with the two recorded independent episodes. It differs from the previous actor-prefix corrective acquisition: there is no new acquisition, hybrid actor prefix, target repair or recovery filter.

The incoming policy is the retained Bfree 10k checkpoint, policy hash `c107f02196502b2e2fe8aed52cea8691e5204c27ef413adfb5fcbd2a41b1bcf0`. Both children receive identical incoming policy parameters, Adam moments/counters, private PCG64 state, fixed original observation normalization, batch indices, architecture and update budget. The unchanged parent is a third evaluation control.

The recorded higher-weight teacher passes the aggregate 5% complete-cost guard. One paired guided episode is approximately 15% more expensive than its independent counterpart; the other is cheaper. This requested comparison uses both true successful guided episodes. It deliberately omits v2's unexecuted per-pair fallback, which would have substituted independent rows for the more expensive guided episode and therefore answered a different data question.

Each arm receives the exact 4,064 original bootstrap labels and the same 32 accepted v2 recovery rows, matching v2's intended common prefix. Each appends 2,000 actual pre-action observation/executed-action pairs: independent `v2_r0_trial_raw_0/1` versus higher-weight `v2_r0_trial_guided1_0/1`. Each arm therefore has 6,096 rows. The four saved teachers must each have completed all 1,000 controls successfully; their complete costs and full reset states, warmstarts and integration snapshots are checked. Action disagreement is diagnostic and never rejects these data.

Each child receives exactly 2,000 Adam updates, batch 256, learning rate 0.0003, parameter-mean proximity weight 0.01 and anchor refresh 250. These are the intended v2 child settings; the incoming Bfree fitting block had zero proximity. Checkpoints 500, 1,000 and 2,000 resume the same fitting block, retaining the exact Adam/minibatch stream and active proximity anchor. No checkpoint is selected by observed outcomes.

All seven fixed policies (parent plus both children at all three checkpoints) receive the same four learning-curve starts rooted at 950110000. Parent and both final children receive 16 fresh paired primary starts rooted at 950100000. The native task, clipped 17-dimensional observations, bounded torque execution and complete 1,000-control horizon remain unchanged.

The guided child advances only if its mean complete cost is at least 5% lower than both parent and independent child, with success count, full survival count and mean executed controls each nondecreasing against both. This incremental criterion does not require prior standalone qualification. If the primary criterion passes, all three final policies receive 16 fresh paired confirmation starts rooted at 950120000, with the same criterion. Otherwise the experiment stops. No extra seed, label, coupling weight, update count or checkpoint retry is allowed. A confirmed improvement requires a separately frozen second acquisition–learning round before any loop claim.

Finite maximum work is 124,000 requested live controls, 1,400,000 neural rows, 1,024,000 backward rows and 4,000 Adam steps; the exact worst-case schedule requires 1,233,344 neural rows. No planner/model controls are permitted. Every control, inference, backward pass and optimizer step is metered; all complete episodes preserve full simulator snapshots and costs. Runtime failure retains partial evidence and stops the run. Preparation, source checks, testing, plotting and transfer overhead are reported separately.

The saved teacher-to-student cost gap is reported with its scope: teacher acquisition starts and fresh student starts differ. Pairwise student cost and survival differences are reported on identical fresh starts. Two teacher episodes and 16 evaluation starts are development evidence; neither novelty, population benefit nor CIO–GPS reproduction failure follows.

Implementation: `scripts/diagnostics/guided_data_comparison.py prepare --out NEW_RUN --feedback SAVED_V2 --experience SAVED_V1`, followed once by `NEW_RUN/source/scripts/diagnostics/guided_data_comparison.py worker --out NEW_RUN`. Preparation makes a create-only source/configuration/checkpoint snapshot, validates the saved data and seals its supplied input hashes. Worker verification refuses changed source, configuration, inputs or an existing evidence directory.
